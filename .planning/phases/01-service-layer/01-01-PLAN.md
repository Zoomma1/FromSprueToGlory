Create `server/src/lib/errors.ts` with an `AppError` base class and five subclasses. Use `Object.setPrototypeOf(this, new.target.prototype)` in the AppError constructor to fix TypeScript's broken `instanceof` for Error subclasses. Export all classes individually (no barrel, direct imports only per project convention).

```typescript
export class AppError extends Error {
  constructor(public readonly statusCode: number, message: string) {
    super(message);
    this.name = this.constructor.name;
    Object.setPrototypeOf(this, new.target.prototype);
  }
}
export class NotFoundError extends AppError {
  constructor(message = 'Not found') { super(404, message); }
}
export class ValidationError extends AppError {
  constructor(message = 'Validation failed', public readonly details?: unknown) { super(400, message); }
}
export class ForbiddenError extends AppError {
  constructor(message = 'Forbidden') { super(403, message); }
}
export class ConflictError extends AppError {
  constructor(message = 'Conflict') { super(409, message); }
}
export class UnauthorizedError extends AppError {
  constructor(message = 'Unauthorized') { super(401, message); }
}
```

Then update `server/src/app.ts`:
1. Add `import type { ErrorRequestHandler } from 'express';` and `import { AppError } from './lib/errors';` at the top.
2. Define the error handler before `createApp`:
```typescript
const errorHandler: ErrorRequestHandler = (err, _req, res, _next) => {
  if (err instanceof AppError) {
    const body: Record<string, unknown> = { error: err.message };
    if ('details' in err && (err as ValidationError).details !== undefined) {
      body.details = (err as ValidationError).details;
    }
    res.status(err.statusCode).json(body);
    return;
  }
  console.error('Unhandled error:', err);
  res.status(500).json({ error: 'Internal server error' });
};
```
3. At the bottom of `createApp()`, after all `app.use('/api/...')` mounts and before `return app;`, add: `app.use(errorHandler);`

Note: Route handlers will still use try-catch or direct await for now — async errors are forwarded via the existing pattern. The error handler is now in place for when service-thrown errors propagate up. Do NOT add `express-async-errors` — the project decision is no new dependencies. Route handlers will call `next(err)` in the catch block during extraction (Task 2 establishes this).

Actually re-read CONTEXT.md: "Route handlers have no try-catch". To achieve this without a new package, wrap each async route handler in a utility. Define a tiny inline wrapper in app.ts or a new `server/src/lib/async-handler.ts`:
```typescript
// server/src/lib/async-handler.ts
import type { Request, Response, NextFunction, RequestHandler } from 'express';
export function asyncHandler(
  fn: (req: Request, res: Response, next: NextFunction) => Promise<void>,
): RequestHandler {
  return (req, res, next) => fn(req, res, next).catch(next);
}
```
This wrapper catches promise rejections and passes them to `next(err)`, which reaches the error handler. No new dependency, zero boilerplate in route handlers. Route files import `asyncHandler` and wrap each handler.
